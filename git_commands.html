1 Initialization

Start a brand-new Git repository, or remove one entirely.

git init

Creates a new, empty Git repository in the current directory. It adds a hidden .git folder that stores all version-control data — every commit, branch, and configuration for this project. Run it once per project.

bash 
$ git init
# Initialized empty Git repository in /path/to/project/.git/

git init "project name"

Creates a new folder with the given name and initializes a Git repository inside it — all in one step. Useful when you want to start a fresh project without creating the directory manually first.

bash 
$ git init my-login-project
# Initialized empty Git repository in .../my-login-project/.git/

rm -rf .git

Deletes the Git repository entirely by removing the hidden .git folder. All commit history, branches, and configuration for this project are gone — the files remain, but they are no longer tracked.

bash 
$ rm -rf .git
Flags explained
-r Recursive — delete folders and everything inside them.
-f Force — never ask for confirmation, ignore missing files.
⚠ This is irreversible. The entire history is destroyed. Use only when you truly want to un-track the project.

2 Configuration

Set who you are, at the global (machine-wide) or local (per-repository) level.

git config --global user.name "your name"

Sets the author name used in commits for every repository on this machine. This is the identity attached to your commits.

bash 
$ git config --global user.name "Ahmed Ibrahim"
Flags explained
--global Applies to all repositories for the current OS user (stored in ~/.gitconfig).

git config --global user.email "your email"

Sets the author email for all repositories. Used by GitHub/GitLab to link commits to your account, so it should match the email on your hosting provider.

bash 
$ git config --global user.email "ahmed@example.com"

git config --local user.name "your name"

Sets the author name for this repository only. Overrides the global value. Stored in .git/config inside the repo. Useful when you contribute to a project with a different identity.

bash 
$ git config --local user.name "Work Account"
Flags explained
--local Applies only to the current repository (stored in .git/config).

git config --local user.email "your email"

Sets the author email for this repository only. Same override logic as the local name above.

bash 
$ git config --local user.email "work@company.com"

git config --global user.name  /  git config --global user.email

Reads (rather than sets) the configured value. Omit the value argument to print what is currently stored at that level.

bash 
$ git config --global user.name
# Ahmed Ibrahim

git config --local user.name  /  git config --local user.email

Reads the repository-specific value. If no local value is set, this returns nothing (the global value is used instead at commit time).

bash 
$ git config --local user.email

git config --list

Lists every configuration value currently in effect — system, global, and local — in one flat output. Local values appear last and win when duplicated. Add --show-origin to see which file each value comes from.

bash 
$ git config --list
user.name=Ahmed Ibrahim
user.email=ahmed@example.com
core.autocrlf=true

git config --global --unset user.name

Removes the specified key from the global config. Useful when you set a value by mistake or want to fall back to a lower-priority setting.

bash 
$ git config --global --unset user.name
Flags explained
--unset Deletes the named key from the chosen config level.

git config --global --unset user.email

Same as above, but removes the global email key.

bash 
$ git config --global --unset user.email

3 Aliasing

Create short nicknames for long commands.

git config --global alias."alias name" "command"

The general form: alias.<name> <command> maps a short word to any Git command. Use quotes around commands that contain spaces. The alias is invoked as git <name>.

bash 
$ git config --global alias."br" branch

git config --global alias.st status

Creates git st as a shortcut for git status. The most popular alias — saves three keystrokes per check.

bash 
$ git config --global alias.st status
$ git st
# On branch main — nothing to commit, working tree clean

git config --global alias.br branch

Creates git br for git branch.

bash 
$ git config --global alias.br branch
$ git br
# * main
#   dark-mode

git config --global alias.cm "commit -m"

Creates git cm "message" as shorthand for git commit -m "message". Quotes are required because the command contains a space. Note that you pass the message after the alias: git cm "fix bug".

bash 
$ git config --global alias.cm "commit -m"
$ git cm "Initial commit"
💡 Inside an alias, never include the leading git. Write branch, not git branch.

4 Editing Configuration

Open the raw config file directly in your editor.

git config --global --edit

Opens the global config file (~/.gitconfig) in the editor defined by core.editor. Handy for editing many values at once or adding complex aliases.

bash 
$ git config --global --edit
# opens ~/.gitconfig in your editor
Flags explained
--edit Open the config file in $EDITOR / core.editor instead of editing a single key.

To set which editor opens: git config --global core.editor "code --wait" (VS Code) or "nano".

5 File Operations

Shell commands commonly used alongside Git (not Git itself, but essential).

touch "file name"

Creates an empty file (or updates its timestamp if it already exists). Used to scaffold new files before adding them to Git.

bash 
$ touch index.html style.css script.js

rm -rf "file name"

Deletes a file or folder permanently. Because Git tracks deletions, removing a tracked file and committing records the deletion in history.

bash 
$ rm -rf old-feature/
Flags explained
-r Recursive: descend into directories.
-f Force: suppress
